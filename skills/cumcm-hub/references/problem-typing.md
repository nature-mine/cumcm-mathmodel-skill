# 问题分型

分型只用于生成候选模型族，不直接替用户选择模型。综合题允许每个子问题分别标注多个类型。

| 类型 | 识别信号 | 候选模型族 | 选型前必须核对 |
|---|---|---|---|
| 评价 | 排序、打分、优选、综合指标 | 标准化与加权、PCA/因子分析、熵权、TOPSIS、AHP、模糊评价 | 指标方向、量纲、权重来源、AHP 一致性、排序稳定性 |
| 优化 | 最大/最小、调度、路径、配置、方案设计 | 线性/整数/非线性规划、动态规划、网络流、启发式与元启发式 | 决策变量、目标、硬约束、可行性回代、最优性或下界证据 |
| 预测 | 时间趋势、分类、回归、未来状态 | 回归、时间序列、状态空间、树模型、神经网络 | 时间切分、数据泄漏、基线、误差指标、不确定性 |
| 机理 | 解释演化、传播、作用机制、物理过程 | 微分/差分方程、守恒模型、概率过程、系统动力学、仿真 | 状态变量、参数可辨识性、边界/初值、量纲、极端情形 |
| 综合 | 多阶段或多类型耦合 | 分层建模、评价→优化、预测→决策、机理→校准 | 子模型接口、误差传播、共享变量、阶段依赖和统一口径 |

## 路由步骤

1. 从题面逐问提取动词、对象、输入、约束和显式交付物。
2. 用 `data_profile.md` 核对样本量、字段类型、缺失、异常、时间/空间结构。
3. 为每个子问题写主类型和次类型，不确定时列出歧义及所需证据。
4. 只保留能用现有数据实现、能在竞赛时间内验证、能回答显式交付物的 2–3 条路线。
5. 比较任务匹配、数据匹配、实现成本、验证负担、解释性和失败风险。
6. 向用户给出推荐与拒绝理由；用户可改选候选或指定候选之外的路线，指定路线按同一框架补评估后照办并留痕；确认前不进入正式建模。

## 常见误路由

- 只有排序需求却直接使用预测模型；
- 用复杂模型替代缺失的目标函数或约束；
- 对时序数据随机划分训练/测试集；
- 把相关性写成因果机理；
- 在有负权边的图上使用 Dijkstra；
- 路径或选址模型漏掉连通、容量、子回路或边界约束；
- 用同一评价权重同时充当优化目标且不解释来源。

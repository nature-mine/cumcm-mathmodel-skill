# CUMCM 评审

以只评不改的独立角色审查 CUMCM 工件。评审意见必须能定位到文件、章节、公式、结果行、图号或契约条款；不得用笼统印象替代证据。

开始前读取：

- [最终评审标准](references/review-standards.md)；
- [分步评审检查单](references/step-review-checklists.md)；
- 当前评审 brief、任务契约、声明的待审工件与证据；
- 当届 `cumcm-profile.md`；涉及引用时运行 `scripts/check_references.py`。

## 独立性与权限

- reviewer 不参与待审工件的生产，不修改任何文件、状态、证据账本或图表登记。
- 宿主支持隔离子代理时，必须另起 `cumcm-reviewer` agent thread；最终模式同时派发 3 个
  上下文隔离、互不可见的实例。Codex 和 Claude Code 适用同一规则。
- “隔离”要求新 thread 只收到评审 brief、任务契约、声明工件和冻结 manifest；不得读取
  生产角色隐藏推理或其他盲评席意见。独立 thread 仍可能共享工作区，不等于文件系统隔离。
- reviewer 必须使用宿主可提供的最强机械限制。Claude Code 只开放 `Read/Grep/Glob`；
  Codex 使用 `sandbox_mode="read-only"`、`approval_policy="never"`、
  `web_search="disabled"`，并禁止使用 MCP/app connector。若父会话 live runtime override
  覆盖了只读设置，返回 `blocked`，不得冒充独立评审。
- 宿主版本支持隔离子代理，但角色未部署、功能被配置禁用、限权未生效或并发不足时，返回
  `blocked` 并要求修正配置；不得切换成顺序复评。
- 只有明确确认宿主版本本身没有隔离子代理功能时，才由同一 agent 切换角色顺序复评；
  最终模式仍按 A/B/C 顺序执行三轮并保留三份报告。每份报告首部必须写：
  `self-review, 独立性受限`。
- 同上下文复评对证据不足的严重问题标为 `P0-candidate` 并请求在任一支持隔离子代理的宿主
  中复核；已经机械确认的红线仍直接记 P0。

## 模式选择

### 分步模式

用于单个建模件、代码件或论文件。输入必须包含 `task_id`、任务契约、工件类型、产物路径和依赖证据。

1. 根据工件类型选择对应检查单。
2. 逐条核验契约 `acceptance`，不得把角色自报 PASS 当作证据。
3. 分别执行数学核验、跨材料一致性和官方合规检查。
4. 给每个问题标注 P0/P1/P2、位置、事实证据、影响和最小返工方向。
5. 结论只用：
   - `通过`：所有 acceptance 有证据，且无 P0/P1；允许保留不影响冻结的 P2。
   - `返工`：存在任一 P0/P1、acceptance 失败或关键项无法验证。

reviewer 只输出意见；hub 才能登记证据、冻结状态或创建返工契约。

### 最终模式

用于完整论文包。单席按五维独立评分：

| 维度 | 满分 |
|---|---:|
| 假设合理性 | 20 |
| 建模创造性 | 25 |
| 结果表述清晰性 | 25 |
| 格式规范性 | 15 |
| 参考文献与引用 | 15 |

按以下顺序执行：

1. 写明收到的文件清单、缺失材料和可验证范围。
2. 先扫通用红线；红线不能被总分抵消。
3. 按标准逐维给分、置信度和可定位理由，总分必须等于五项之和。
4. 单列 P0/P1/P2；对无法从结果、账本或来源核实的量化/引用结论不得给“推定通过”。
5. 输出 `submit_ready: yes | no`。有 P0、官方合规项未闭合或必要材料缺失时必须为 `no`。

创新评分看问题特定贡献、机制增量、有效性和相对基线价值。开创性方法可能没有文献先例，**不得仅因无先例而压分**；但无验证、无适用范围或把标准方法改名，不构成创新。

## 三席盲评

hub 先冻结同一份 artifact manifest，再在同一轮同时派发 3 个隔离席位：

- A：综合评委，平衡五维与整篇论证；
- B：侧重创新、决策价值和结论稳健性；
- C：怀疑型应用数学审稿人，侧重正确性、可复现和证据链。

每席只收到本席 brief、论文包和 artifact manifest。三席都以干净或最小父上下文启动；当前
Codex 工具支持时使用 `fork_turns="none"` 或等价选项。reviewer 只返回报告，不在共享工作区
落盘；hub 等三席全部返回后再统一写入席位报告并汇总：

- 汇总首部写 `review_mode: isolated_subagents`；
- 每个维度及总分取三席中位数；
- P0 取并集；
- 任一维度最高与最低相差 `≥15` 分，标记为“争议项”并交用户复核；
- 不用简单平均消解 P0，不让一席查看其他席报告后改分。

若宿主版本支持 subagent、但当前无法同时建立 3 个合规的隔离 thread，本轮必须 `blocked`
并修正部署、权限或并发配置。只有宿主版本本身没有 subagent 功能时才切换为
`sequential_fallback`；汇总首部写 `review_mode: sequential_fallback` 和
`fallback_reason: subagent_unavailable`，并显著披露独立性受限。

## 红线

下列已确认事实直接列 P0：

- 论文引用非 frozen 数字，或量化结论无法在结果文件、代码和 run-log 中追溯；
- 实验结果幻觉、引用幻觉或伪造来源；
- 公式、单位、硬约束或题意错误使主要结论失效；
- 数据泄漏、硬编码答案、异常结果被包装成模型特性；
- 用双 Y 轴、误导坐标、选择性展示等图表反模式支撑主要结论；
- 精确结构图使用文生图，或概念图冒充定量证据；
- 摘要未覆盖关键量化结论；
- 关键章节缺少“机制 → 结果 → 验证 → 解释”中的任一环，导致结论无证据；
- 正文泄漏 agent/prompt/派发/P0 等内部流程语言；
- 匿名、页数、附录源程序、支撑材料或 AI 披露等当届硬性合规失败。

当届规则未核实时标为 `blocked`，不得凭记忆判合规。

## 引用检查边界

`check_references.py` 只机械检查：

- GB/T 7714 常见文献类型的结构、字段和标点；
- 参考文献编号连续唯一；
- 正文引用与文末条目一一对应。

脚本不能证明文献真实存在。reviewer 仍须依据核验记录逐条比对标题、作者、年份、来源和 URL；缺少真实性证据时按引用幻觉风险处理。

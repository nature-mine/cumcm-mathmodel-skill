# CUMCM 编程

把冻结建模件实现为可重复运行的代码、结果和车道 A 数据图。不得改变模型口径、在代码里硬编码预期答案，或把报错包装成模型特性。

## 前置输入

开始前读取任务契约、冻结的 `reports/analysis_modeling_P<i>.md`、相关数据来源、`evidence/ledger.md` 和 [数据图规则](references/figure-rules.md)。

- 只读取 `input/`；清洗、修复和格式转换写入 `data/` 并记录来源变换。
- 契约路径必须是工作区相对路径，禁止绝对路径、`../` 和未声明网络输入。
- 建模接口缺字段、单位、公式、边界或验收判据时返回 `blocked`，不得自行改模型。

## 执行步骤

### 1. 核对环境与数据

- 先确认 env-doctor Tier 0 为 `OK`。
- 有附件时运行 `scripts/profile_data.py` 生成 `data_profile.md`；XLSX 默认剖析全部工作表，
  仅需单表时显式传 `--sheet`。剖析是选型依据，不是模型结论。
- 按建模件检查所需 Tier 1 包；只安装缺失且已确认需要的依赖，使用 `uv add` 并记录命令。
- 校验行数、字段、单位、缺失、重复、范围和主键；任何修复另存 `data/`。

### 2. 实现与验证

- 代码写入 `code/`，入口参数、输入和输出显式化。
- 所有随机过程使用固定种子，并把种子写入运行记录。
- 使用小型确定性样例检查核心公式、边界和失败路径。
- 优化问题对最终解逐条回代硬约束，不以求解器状态替代验证。
- 预测问题防止时间、实体和预处理泄漏，并保留基线对比。
- 运行建模件约定的灵敏度、稳健性或消融实验。
- 捕获失败时保留非零退出状态和可定位原因；禁止静默降级为伪结果。

### 3. 落盘结果

- 机器可读结果写入 `results/`，列名、单位、精度和场景口径与建模件一致。
- `results/run-log.md` 记录任务、时间、命令、输入、参数、依赖、随机种子、退出状态、输出和约束/测试摘要。
- 不覆盖已冻结结果；变更必须使用新文件并交 hub 走 supersession。
- 论文使用的每个量化结果准备唯一的 `evidence_id`，但由 hub 在评审通过后登记并冻结。

### 4. 生成车道 A 图

- 每张图先写明要证明的结论，再按数据形态选图。
- 图由代码从真实结果生成；保存高分辨率 PNG，并在可行时同时保存 SVG 或 PDF。
- 执行反模式、中文字体、灰度/色盲和视觉自检。
- 在 `figure_registry.md` 登记 `lane=A`、`status=done`、生成脚本、结果来源、run-log、章节和路径。
- 结构图与概念图不在本 Skill 生成，分别交给 writer 加载 `cumcm-diagram`。

## 必须产出

以任务契约为准，至少包含：

- `code/` 下的可运行源程序与必要配置；
- `results/` 下的机器可读结果和 `run-log.md`；
- 建模件要求的验证、约束回代和灵敏度结果；
- 车道 A 图及其生成脚本；
- 待登记证据和图表 provenance。

不得在编程阶段改写论文，也不得为“符合预期”手工修改结果文件。

## 反馈契约

按 `Task feedback` 逐条报告验收结果、实际命令、输出、种子、约束回代、失败用例和待登记证据。`verdict=ready_for_review` 只表示可送独立评审；有任一失败条款、不可复现结果或接口歧义时返回 `blocked`。
